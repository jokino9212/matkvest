## Объём изменений

- В `assets/ui/legacy-vue-actions.js` добавлен независимый от DOM и хранилища адаптер `trainingPlanActions` для `back`, `earlier`, `later`, `toggle`, `remove`, `start`, `rebuild`, `delete`, `launch`, `complete`.
- Объект обработчиков создаётся заново для каждого отображения плана. Перед вызовом проверяются актуальность экрана и наличие блокирующего диалога.
- `renderTrainingPlanView` в `index.html` теперь передаёт эти обработчики в Vue. Старая HTML-разметка и реальные функции плана остаются в файле; расходы, XP, монеты и правила выполнения не менялись.
- Сохранён HTML fallback, когда внешний адаптер недоступен. В него также добавлена проверка актуальности экрана.
- Версии ресурсов и PWA cache синхронизированы: `matkvest-iphone-v272`.

## Подтверждённый дефект до исправления

Новый браузерный тест обнаружил, что после выхода из плана на старом HTML fallback сохранённая ссылка на отсоединённую кнопку могла продолжить вызывать обработчик. В Vue-режиме stale-screen guard уже работал. В патч добавлен guard непосредственно для fallback; повторный браузерный прогон прошёл.

Отдельно исправлены две **ошибки тестовой инфраструктуры**, не приложения:
1. Тест нормализует допустимое отсутствие `itemId` у кнопок без привязки к пункту: Vue передаёт `undefined`, старый HTML fallback — пустую строку.
2. Скрипт публикации первоначально ожидал `?v=271` для двух модулей вместо `?v=272`; публикация отказалась от записи. Условие исправлено, а повторная публикация разрешена только для точного SHA256 HTML из завершённой полной регрессии.

## Ограничения и следующий этап

PR #131 остаётся draft. Нет merge, деплоя production или backend-интеграции. Сохранена старая бизнес-логика планов: вынесены только UI-действия.

Дальше целесообразно по отдельности переносить обработчики школьных упражнений и журнала попыток. Каждый новый этап должен сохранять fallback, проходить контроль нажатий/роутинга и хранение прогресса после F5 без сети. Старые одноразовые v271/v272 gate-workflow оставлены только для ручного запуска, чтобы при новых коммитах не применять патчи к неизвестной версии HTML.
