## Подтверждённый дефект Escape: преподаватель → профили
- На v279 при входе в `openProfiles()` с панели преподавателя `mk854Route()` становится `{screen:"profiles"}` и глубина истории равна 1. По Escape глобальная обработка закрывает окно и возвращает `{screen:"home"}`, `mainView` содержит домашний экран, но `teacherUnlocked===true`. Воспроизводится и с Vue и без Vue (390px).
- При открытии резервной копии из преподавательской панели маршрут остаётся `home`, а по Escape панель сохраняется. Это демонстрирует различие возврата между двумя административными окнами.
- Исходный модальный focus trap вызывает `closeModal()` по Escape. Бизнес-логика разрешения доступа не меняется; требуемое исправление должно восстанавливать только преподавательскую панель после закрытия **профилей, открытых непосредственно оттуда**, не вмешиваться в обычную навигацию профилей и не влиять на другие диалоги.
- После исправления тестировать Escape, кнопку закрытия, фокус на вызвавшей кнопке, отсутствие возврата в преподавателя при открытии профилей обычным пользователем, сохранность profile ID, XP, монет, истории попыток.

## Подтверждённые дефекты и точечные исправления

1. **Преподаватель → Профили → Escape**. Исходная `profiles:()=>openProfiles()` добавляла `{screen:"profiles"}` в историю поверх временной преподавательской панели. Escape возвращал `home`, при этом `teacherUnlocked===true`. Исправлено **только в преподавательской панели**: её действие вызывает оригинальный рендерер `MK854_CORE_OPEN_PROFILES()` без добавления маршрута. Обычный ученический переход в профили продолжает использовать историю. Фокус по Escape восстанавливается на кнопке «Новый ученик»; без Vue тоже PASS.
2. **Устаревшие вкладки Vue-магазина могли менять маршрут.** Выявлено и воспроизведено новым тестом после замены inline HTML: сохранённая отсоединённая кнопка Vue `mountStoreTabs` сохраняла прямой callback `openStoreTab(id)` и переключала `collection` на `avatars` из уже закрытого контейнера. Read-only trace https://github.com/jokino9212/matkvest/actions/runs/45415798064 выявил отдельный UX91 Vue-мост. Исправлено: `storeTabActions` с whitelist категорий + `isCurrentTabHost` проверяет, что исходный Vue-host остаётся в открытом модальном окне. В HTML fallback inline onclick/onchange удалены, навигация делегирована через живой `#modal` и ту же проверку. Бизнес-логика магазина/покупок/наград не менялась.
3. **Мобильная навигация — корректировка теста, не дефект приложения.** При ширине 390 px панель desktop `.shop-tabs` по CSS скрыта, используется видимый `select.mk-ux91-category-select`. Ранние версии нового теста пытались клавиатурой активировать скрытую вкладку и требовали её видимости. Исправлена проверка: Enter/Space на видимой настольной кнопке, `selectOption` в мобильном списке, `data-store-active` проверяется независимо от CSS-видимости.
4. **Пропуск задания деления столбиком**: исходный редкий timeout не воспроизведён ни в 12 независимых preflight-запусках, ни в 12 повторениях релизного gate; в обоих 12/12 PASS. Отдельная PWA-регрессия также PASS на делении, включая подтверждение и сохранение результата. Никаких неподтверждённых исправлений `mk872RequestExerciseSkip`, проверки ответов или наград не делалось.

Изменения в `assets/ui/legacy-vue-actions.js` и SHA-fenced `audits/legacy_teacher_escape_store_v280_patch.py` ограничены представлением и UI-диспетчеризацией. `main`, production, backend не затронуты.
