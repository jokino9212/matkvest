## Acceptance stages
1. Read-only backup review: exact v306 full export fixture, source labels, group stable profile IDs, compare full payload; identical snapshots collapse in preview, conflicts cannot auto-commit. Current module is only preflight, not schema authenticity/ownership validation. Synthetic tests now; genuine v306 fixture from browser gate later. Legacy profiles with no ID and same-name different IDs require explicit review. Never sum/max snapshot balances or infer ownership from name. No deletion, no upload in preflight.
2. Recover actual private R7-R5 backend ZIP and verify digest/manifest against owner decision before changing Python or schema. Existing account UI signs in by email; API register accepts student/tutor only. Add unique normalized username for students without email, optional verified contact, existing email compatibility; parent-managed access with explicit relationship/consent, not self-asserted privileges. Password storage and auth protections on backend; throttling, single-use hashed recovery tokens, expiry, revocation, neutral errors, no credentials in logs or localStorage. Decide parent recovery and ownership before activation; test role boundaries, account linking, session invalidation.
3. Migration: preserve original backups on both devices, validate exact schema, show per-profile before/after for XP, coins, inventory, achievements, receipts and history. Reconcile only causally identifiable operations; unknown/divergent monetary histories require manual review, not max or sum. Preserve archived/sold item tombstones, mark imported attempts as historical, do not grant reward on import. Explicit authorized owner approval and one-time scoped claim code (hashed, expiring, rate-limited, revoke/reissue). Atomic server transaction and stable import identity, duplicate/replay and rollback tests; separate import audit, no public self-credit. Recheck exact five pupils individually before cutover, retain originals read-only until confirmed.
4. Teacher lesson: signed-in tutor selects linked pupil with consent and server-scoped grant. No impersonation or pupil password. Actor and pupil distinct; explicit lesson context, server verifies every permit/submit, revocation, concurrent independent devices and retries. Keep pupil self-study session distinct; attribution based on server actor, not client string. Existing Free limits remain unless explicitly changed. Offline block queue immutable owner/actor/profile/context, no optimistic reward.
5. Homework: tutor assigns supported topic/stage/block count and optional due date; student sees assigned tasks, works from own account. Server-issued assignment/task IDs, authorized tutor link, attempt association and idempotent progress. Distinguish not started/in progress/completed, late separately; confirmed submissions only for completion. Show answers/errors/corrections/skips and elapsed active time when available, clearly label pending and imported records; do not claim elapsed time or answer telemetry not captured. Reports scoped to linked pupil, with revocation, no unrelated student data. No double credit or rewards merely for completing assignment. Same-origin API, offline queue and existing entitlements.
6. UX based on approved demo, responsive 320/390/1280, clear login/register/local/migration paths, keyboard, errors, focus, accessibly labelled controls. Integrate exact v306 runtime and policy changes in isolated branch; verify Vue/fallback, actual API browser + PostgreSQL, security and PWA. No live cutover until separately authorized.
