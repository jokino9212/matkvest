## Этап 20 — дополнительный аудит кеша (продолжение)

Найдено существенное ограничение предыдущего частичного патча: запрет по известным приватным URL не исключал попадание неизвестного маршрута, возвращающего HTML, в offline-кеш `index.html`. Это риск при будущей аутентификации и серверном роутинге.

Вместо denylist реализован allowlist в `sw.js`:
- Навигации обрабатываются только для корня приложения и `index.html` в области действия SW.
- В Cache Storage допускаются только явно публичные статические пути `assets/`, `images/`, `icons/` с ожидаемыми типами ресурсов, а также manifest.
- Ответы с `Cache-Control: private` или `no-store` не кешируются.
- Запросы с явными заголовками `Authorization` или `Cookie` исключены.
- Неизвестные запросы и приватные API не перехватываются; браузер отправляет их в сеть напрямую.
- Дополнены тесты против cache poisoning и обхода API под маской PNG.

**Ограничение:** до full Gate и браузерных тестов нельзя утверждать, что ограничения на кеширование статических ресурсов не влияют на офлайн-поведение редких ресурсов приложения. В production ничего не публиковалось. Backend ZIP в доступных файлах/Drive по имени всё ещё не найден.

## Этап 20 — защита от кеширования перенаправлений

Во время следующего прохода обнаружен ещё один пограничный случай: даже запрос к разрешённому публичному URL может получить редирект на приватный документ. В `sw.js` добавлена проверка `!response.redirected` перед обеими операциями записи в Cache Storage (HTML shell и статические ресурсы). Это защищает кеш от ответов с перенаправлением вне ожидаемого публичного маршрута.

Тест `audits/stage20_sw_privacy_test.cjs` дополнен сценариями с `Cache-Control: private, no-store`, редиректом статического файла и редиректом HTML-навигации, а также имитацией отсутствия сети с чтением cached shell. Остаются предварительными: реальный GitHub Actions Gate / Chromium E2E **не подтверждены**; доступные combined statuses и PR-triggered workflow runs для коммита теста пусты, что не означает PASS.

Текущая ветка: `audit/backend-stage20-20261106`. Production `main` не менялся. Не сливать защитный патч в production без отдельной полноценной проверки PWA.
